# Demo and target

The demo proves the design. It is not the platform IT would run. Both keep the same seven rules, so tools move over unchanged.

## The seven rules
1. **Identity**: one person, one account. Tools have no logins.
2. **Structure**: hub, space, tool. Permanent ids.
3. **Access**: one model, four roles, four levels. The database enforces.
4. **Tool kit**: every tool is written against the same two kit lines. Version 1 only gets additions.
5. **Data**: each tool has its own tables; standard columns; one sharing rule per table; row rules written by the platform.
6. **Releases**: upload, check, preview, make live, roll back. Versions never change.
7. **Audit**: append-only.

## What the demo runs on
:::compare
Demo | Target
Pages | GitHub Pages: plain HTML, CSS and JavaScript, no framework, no outside files | IT's web server inside the company's domains, with security headers
Sign-in | Email or username with password | Company sign-in with second factor
Database | One Supabase project; only functions are exposed | IT's database
Uploaded tools | A private file store | IT's file store
Accounts made by IT | Written into the sign-in service's tables | IT's directory
:::

## What IT would look at first
- "Threats, one by one": who could try what, what stops him, what is left over.
- "Who can give what to whom": how rights are handed on and taken back.
- "Where data lives, and what happens to it": every store, every way out, what a delete does.
- The list of exposed functions, and the check at the top of each.
- The sealed frame, the hostile-tool test and the rehearsal.
- "Open gaps and hand-over": everything weaker than production, in one place.

## Open gaps, accepted for a demo with sample data
- No company sign-in and no second factor yet.
- A manager can publish alone; no second reviewer yet.
- No quotas, no export, and the last save wins when two people change one row.
- A delete is final: no bin, and no backup of the site's own.
- Whoever can push to the repository changes the pages for everyone, with no review.
- Accounts made by IT, and passwords reset by IT: IT knows the temporary password until the person chose his own; it counts 7 days.
- GitHub Pages cannot send security headers.
