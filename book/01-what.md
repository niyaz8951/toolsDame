# What DAME is

DAME is one website for the working tools of every department. Each department gets its own space. Inside a space, its people build and use tools: calculators, converters, trackers, extractors. The site gives every tool the same look, the same sign-in and one safe place for data.

=> One site | A space per department | Tools inside each space

## The problem it solves
:::cards
Tools live on laptops | Excel files and loose HTML pages. Nobody knows which version is the right one | today
No sign-in | A loose page cannot hold shared data safely | today
AI builds a page in an hour | But people cannot publish it, share it or connect it to a database without IT | new
IT cannot host every small tool | Not by hand, one review at a time | limit
:::

## The idea
- IT runs **one** site and controls who gets in, which spaces exist and the rules.
- Each department's admin makes tools **from the site itself**: no repository, no server, no SQL.
- The person describes the tool, the site prepares the request for the AI, checks what comes back, and publishes it.
- Whatever a team uploads runs sealed: it cannot reach the internet, the session or another team's data.

## Who it is for
:::cards
People who use tools | Open a tile, use the tool. Nothing to install
People who build tools | Not developers. They know their work and can describe it
Department admins | Decide which tools exist in their space and who gets them
IT | Decides who is in, sets the rules, reads the audit
:::

## What this site is today
> This is a demonstration. It runs on GitHub Pages and one Supabase project, with sample data only. It keeps the same seven rules the company platform would keep, so a tool built here would run there unchanged.
